# 第 5 章 DeepSeek V4 架构详解

## 本章导读

上一章我们了解了 GGUF 文件的物理结构。这章来看"逻辑结构"--DeepSeek V4 模型到底长什么样。我们会把 `DS4_SHAPE_FLASH` 里的每个参数翻译成人话，并用一张图把整个模型架构画出来。

## 5.1 模型的"身份证"：DS4_SHAPE_FLASH

在 `ds4.c:535`，有一个结构体常量定义了 DeepSeek V4 Flash 的全部架构参数：

```c
static const ds4_shape DS4_SHAPE_FLASH = {
    .name = "DeepSeek V4 Flash",
    .n_layer = 43,          // Transformer 层数
    .n_embd = 4096,         // 嵌入维度（隐藏层宽度）
    .n_vocab = 129280,      // 词表大小
    .n_head = 64,           // 查询头数
    .n_head_kv = 1,         // KV 头数（GQA 压缩比 64:1）
    .n_head_dim = 512,      // 每个头的维度
    .n_rot = 64,            // RoPE 旋转维度
    .n_out_group = 8,       // 输出分组数
    .n_lora_q = 1024,       // Q 投影低秩维度
    .n_lora_o = 1024,       // 输出投影低秩维度
    .n_expert = 256,        // 专家总数
    .n_expert_used = 6,     // 每次激活的专家数
    .n_expert_shared = 1,   // 共享专家数
    .n_ff_exp = 2048,       // 专家 FFN 宽度
    .n_swa = 128,           // 滑动窗口大小
    .n_hc = 4,              // 头通道分组数
    .n_indexer_top_k = 512, // 索引器 top-k
    // ...
};
```

别被这些数字吓到，我们逐个解释。

## 5.2 整体架构：43 层的"接力赛"

DeepSeek V4 Flash 由 43 个 Transformer 层堆叠而成。数据从第 0 层进入，经过 43 层处理后输出：

```
输入 token -> Embedding 查表
    │
    ▼
┌─────────────────┐
│  Layer 0         │  ← 每层做两件事：Attention + FFN/MoE
├─────────────────┤
│  Layer 1         │
├─────────────────┤
│  ...             │
├─────────────────┤
│  Layer 42        │
└─────────────────┘
    │
    ▼
Output Norm -> Output Head -> logits (129280 个分数)
```

### 每一层内部

```
        输入向量 (4096 维)
            │
            ▼
    ┌─── Attention ───────────────────┐
    │  AttnNorm (RMSNorm)              │
    │  Q/K/V 投影 + RoPE              │
    │  注意力计算 + SWA 窗口           │
    │  输出投影                        │
    └──────────┬───────────────────────┘
               │ （残差连接：加上输入）
               ▼
    ┌─── FFN / MoE ──────────────────┐
    │  FFNNorm (RMSNorm)              │
    │  路由门控：256 个专家选 6 个     │
    │  6 个路由专家 + 1 个共享专家     │
    │  SwiGLU 激活                     │
    └──────────┬───────────────────────┘
               │ （残差连接：加上之前的结果）
               ▼
        输出向量 (4096 维) -> 传给下一层
```

这就是一个 Transformer 层。43 层叠在一起，就是完整的模型。

## 5.3 嵌入维度：n_embd = 4096

`n_embd` 是模型的"思考宽度"。每个 token 被表示为一个 4096 维的向量，每一层的中间计算都在 4096 维空间中进行。

数字越大，模型"想得越深"，但计算量也越大。4096 是一个中等偏大的值--比 Llama-3-8B 的 4096 一样，但 DeepSeek V4 Flash 通过 MoE 架构在同样宽度下达到了更强的能力。

---

## 5.4 注意力机制：MLA + GQA + SWA + HC

这是 DeepSeek V4 最有特色的部分。它同时用了四种技术来优化注意力。

### 5.4.1 GQA：64 个查询头，1 个 KV 头

```
传统 MHA（多头注意力）:
  64 个 Query 头, 64 个 Key 头, 64 个 Value 头
  -> KV 缓存巨大

GQA（分组查询注意力）:
  64 个 Query 头, 1 个 Key 头, 1 个 Value 头
  -> 64 个 Query 头共享同 1 组 KV
  -> KV 缓存缩小 64 倍！
```

在 `DS4_SHAPE_FLASH` 中：
- `n_head = 64`：64 个查询头
- `n_head_kv = 1`：只有 1 个 KV 头

压缩比 64:1 极其激进。这意味着所有查询头共享同一份 Key 和 Value，大幅减少了 KV 缓存的内存占用。

> **为什么能这样做？** 研究发现，很多注意力头学到的模式是相似的。共享 KV 不会显著降低质量，但能把长上下文的内存成本降到可接受的范围。

### 5.4.2 MLA：低秩投影

光靠 GQA 压缩还不够。DeepSeek V4 还用了 **MLA（Multi-head Latent Attention，多头潜在注意力）**，通过低秩矩阵分解来压缩 Q/K/V 的投影。

先明确几个变量的含义：

- **`x`**：当前层的输入向量（经 RMSNorm 处理后），维度 `n_embd = 4096`
- **`W_q`**：标准注意力中的 Q 投影权重矩阵，形状 **[32768, 4096]**（行=输出维度，列=输入维度）。`32768 = 64 头 × 512 维/头`
- **`Q`**：投影后的 Query 向量，维度 `n_head × n_head_dim = 64 × 512 = 32768`
- **`c`**：MLA 压缩后的低秩向量，维度 `n_lora_q = 1024`

```
标准注意力（一步到位）:
  Q = W_q × x
  W_q 形状: [32768, 4096]   (输出32768维, 输入4096维)
  x 形状:   [4096]           (输入向量)
  Q 形状:   [32768]          (64头 × 512维)
  参数量:   32768 × 4096 ≈ 1.34 亿

MLA 低秩分解（两步走，先压缩再还原）:
  压缩: c = W_q_a × x       (4096 -> 1024)
  还原: Q = W_q_b × c       (1024 -> 32768)
  W_q_a 形状: [1024, 4096]    (输出1024维, 输入4096维)
  W_q_b 形状: [32768, 1024]   (输出32768维, 输入1024维)
  c 形状:     [1024]           (压缩后的低秩向量)
  参数量:     1024×4096 + 32768×1024 ≈ 0.38 亿 (减少约 3.5 倍)
```

在 `ds4_layer_weights` 中对应（`ds4.c:5076-5078`）：
- `attn_q_a`：压缩矩阵，形状 [1024, 4096]（`dim[0]=n_embd=4096`, `dim[1]=n_lora_q=1024`）
- `attn_q_b`：还原矩阵，形状 [32768, 1024]（`dim[0]=n_lora_q=1024`, `dim[1]=q_dim=32768`）
- `attn_kv_a_mqa`：KV 压缩矩阵（4096 -> 512）
- `attn_k_b` / `attn_v_b`：KV 还原矩阵

`n_lora_q = 1024` 就是低秩维度（也叫"秩"）。通过先压缩到 1024 维再还原回 32768 维，Q 投影的参数量从 1.34 亿降到 0.38 亿，减少约 3.5 倍，同时几乎不影响模型表达能力--因为 1024 维足以捕获 Q 所需的主要信息。

> **为什么叫"低秩"？** 原始矩阵 `W_q` 的秩最多是 4096（即 min(32768, 4096)）。分解后 `W_q ≈ W_q_b × W_q_a`，秩最多是 1024。"低秩"就是用比原始矩阵更低的秩来近似它，牺牲少量精度换取大幅参数减少。

### 5.4.3 低秩投影的数学原理

上一节介绍了 MLA 的压缩-还原两步走，这节解释它背后的数学原理。

#### 矩阵分解的直觉

标准投影做的是一次矩阵乘法：`Q = W_q × x`。`W_q` 是一个 `[32768, 4096]` 的大矩阵。MLA 把这个大矩阵拆成两个小矩阵的乘积：

```
W_q ≈ W_q_b × W_q_a
     [32768,1024] [1024,4096]
```

从矩阵乘法的角度看，这等于在输入 `x` 和输出 `Q` 之间插入了一个 1024 维的"瓶颈"：

```
x (4096维) --W_q_a--> c (1024维) --W_q_b--> Q (32768维)
              压缩                    还原
```

#### 为什么有效？

关键在于**信息冗余**。虽然 `W_q` 有 32768×4096 个参数，但这些参数中有很多冗余--`Q` 的 32768 维并非完全独立，它们可以通过一个低维的"潜在因子" `c` 来生成。可以把它想象成：

```
32768 维的 Q 看似复杂，但它的"自由度"只有 1024
-> 1024 维的 c 足以捕获 Q 的主要变化
-> 额外的 32768 - 1024 = 31664 维只是 1024 维的线性组合
```

这就像图片压缩：一张 1080p 图片有 200 万像素，但可以用几百个 JPEG 系数很好地近似。MLA 做的是同样的事--用 1024 个"系数" `c` 来近似 32768 维的 `Q`。

#### 数学上的"秩"

矩阵的**秩（rank）**是这个矩阵中线性无关的行（或列）的最大数量：

```
W_q 的秩 ≤ min(32768, 4096) = 4096
  -> W_q 最多有 4096 个线性无关的列
  -> Q = W_q × x 的输出空间最多是 4096 维子空间

W_q_b × W_q_a 的秩 ≤ min(32768, 1024, 4096) = 1024
  -> 分解后的秩最多是 1024
  -> 输出空间被限制在 1024 维子空间
  -> "低秩" = 用更低的秩来近似原始矩阵
```

#### 参数量与表达能力的权衡

```
标准投影:
  参数量 = 输出维度 × 输入维度 = 32768 × 4096 = 1.34 亿
  表达能力: 秩最高 4096

低秩投影:
  参数量 = 1024×4096 + 32768×1024 = 0.38 亿 (减少 3.5 倍)
  表达能力: 秩最高 1024 (降低了，但够用)
```

**核心权衡**：牺牲少量表达能力（秩从 4096 降到 1024），换取大幅参数减少（3.5 倍）。实践中这个"牺牲"几乎不影响模型质量，因为注意力投影不需要满秩--1024 维的子空间已经足够捕获 token 之间的关键关系。

> **训练时的考量**：低秩投影的另一个好处是减少过拟合风险。参数少了，模型的"记忆容量"降低，更倾向于学习泛化特征而非死记硬背训练数据。这也是 LoRA（Low-Rank Adaptation）微调技术的同一原理。

#### 对 KV 缓存的影响

MLA 对 KV 的压缩更为关键。标准注意力的 KV 缓存存储完整的 K 和 V 向量，而 MLA 只需存储压缩后的低秩向量 `c_kv`（512 维），在需要时再还原：

```
标准: 缓存 K(512维) + V(512维) = 1024 维/token/层
MLA:  缓存 c_kv(512维)          = 512 维/token/层 (减半)
```

配合 GQA 64:1（所有头共享一份 KV），KV 缓存被压缩到极小，这是 DeepSeek V4 能支持超长上下文的关键基础。

### 5.4.4 SWA：滑动窗口注意力

```
n_swa = 128 表示：

普通注意力: 当前 token 要看前面所有 token（计算量随长度线性增长）

SWA 滑动窗口: 当前 token 只看最近 128 个 token
  ┌──────────────────────────┐
  │ ... 旧的历史不看 │ 最近128个 │ 当前 │
  └──────────────────────────┘
                    ↑ 只在这个窗口内算注意力
```

滑动窗口的好处：
- 注意力计算量固定（不管上下文多长，每次只看 128 个）
- 配合 KV 缓存压缩，长上下文的内存成本可控

> **但 SWA 不会让模型"忘记"远处的信息吗？** 不会完全忘记。信息通过多层网络逐层传递--第 1 层看 128 个，第 2 层看第 1 层的输出（间接看到了 256 个），依此类推。43 层堆叠后，感受野远大于 128。

### 5.4.5 HC：头通道分组

```
n_hc = 4 表示：

把注意力头的维度分成 4 组（head-channel 分组）
  每个头 512 维 -> 分成 4 组，每组 128 维
  不同组使用不同的注意力计算方式
```

HC 是 DeepSeek V4 特有的优化，让不同维度的子空间可以有不同的注意力模式。`hc_attn_fn`、`hc_attn_scale`、`hc_attn_base` 这些权重就是控制 HC 分组行为的参数。

### 5.4.6 为什么用 512 维的大头？

回顾一下参数：DeepSeek V4 Flash 每个注意力头 `n_head_dim = 512` 维。这与标准 Transformer 有很大不同：

```
标准 Transformer (如 GPT-2, Llama):
  每头维度: 64-128
  头数:     32-64
  Q 总维度: 32×64 = 2048 ~ 64×128 = 8192

DeepSeek V4 Flash:
  每头维度: 512    ← 比标准大 4-8 倍
  头数:     64
  Q 总维度: 64×512 = 32768
```

为什么用这么大的头？这是 MLA + GQA + SWA 三重优化的配套设计：

1. **MLA 需要大头来分区**：每个头的 512 维分成两部分--448 维内容（不做 RoPE）+ 64 维位置（做 RoPE）。如果头维度太小（如 64），内容部分只有 0 维，MLA 就没有意义了。大头让"内容/位置分离"有足够空间。

2. **GQA 64:1 抵消了大头的计算开销**：标准 MHA 中，64 个头各自有独立的 KV，头维度大意味着 KV 缓存爆炸。但 GQA 让 64 个头共享 1 份 512 维 KV，计算量和缓存与"64 个 8 维小头共享 1 份 KV"一样。

3. **SWA 固定窗口控制注意力成本**：512 维点积比 64 维贵 8 倍，但 SWA 把注意力范围固定在 128 个 token，计算量不随上下文增长。

```
设计哲学:
  大头 (512维) + 少头 (64个) + GQA (共享1份KV) + SWA (固定窗口)
  = 每头信息量大 (512维足够做内容/位置分离)
  + KV缓存极小 (只存1份512维)
  + 注意力计算可控 (窗口固定128)
  + 总参数适中 (MLA低秩压缩投影)
```

> **一句话总结**：512 维大头是 MLA 的前提条件--没有足够大的头维度，就无法实现"内容/位置分离"。GQA 和 SWA 则确保大头的计算和内存成本可控。

## 5.5 MoE：混合专家

这是 DeepSeek V4 最核心的设计。每一层的 FFN 不是一个固定网络，而是 **256 个小网络（专家）中选 6 个**来处理。

### 5.5.1 MoE 的工作方式

```
          输入向量 x (4096 维)
              │
     ┌────────┴────────┐
     │  路由门控 (Gate)  │  ← 一个 [256,4096] 的小矩阵，给每个专家打一个分
     │  输出 256 个分数  │     计算量仅 256×4096 ≈ 100 万次乘加（很小）
     └────────┬────────┘
              │
     选出分数最高的 6 个专家（不是 256 个都算！）
              │
    ┌────┬────┼────┬────┐
    │    │    │    │    │
  专家A 专家B ... 专家F   ← 只对选中的 6 个做 FFN 计算
    │    │    │    │      每个专家计算量 ≈ 1680 万次乘加
    └─6 个专家输出加权求和─┘  6 个总计 ≈ 1 亿次乘加
              │
     ┌────────┴────────┐
     │ 共享专家 (始终激活) │  ← 每次都参与计算，同样 ≈ 1680 万次乘加
     └────────┬────────┘
              │
     加权求和
              │
              ▼
          输出向量 (4096 维)
```

> **关键点：路由门控只打分，不计算专家**。门控层是一个 `[256, 4096]` 的矩阵（`ffn_gate_inp`），做一次矩阵-向量乘法产出 **256 个分数**，计算量仅 `256 × 4096 ≈ 100 万`次乘加。真正昂贵的是**专家 FFN 计算**——每个专家包含 3 个矩阵（gate / up / down），各 `[2048, 4096]`，合计 `3 × 2048 × 4096 ≈ 2520 万`次乘加。如果 256 个专家全算，需要 `256 × 2520 万 ≈ 64.5 亿`次乘加；**只算 6 个**，只需 `6 × 2520 万 ≈ 1.51 亿`次乘加。MoE 的计算量比 dense 减少了约 `256 / 6 ≈ 43` 倍，路由门控那 `100 万` 开销相比之下微不足道。源码依据：`layer_routed_moe_one` 内层循环用 `DS4_N_EXPERT_USED=6`（`ds4.c:10837`、`ds4.c:10871`），只在 `selected[i]` 这 6 个专家上跑 FFN。

### 5.5.2 参数解读

- `n_expert = 256`：每层有 256 个路由专家
- `n_expert_used = 6`：每次只激活 6 个（256 选 6，只有 2.3% 的专家在工作）
- `n_expert_shared = 1`：1 个共享专家，**每次都参与计算**，负责处理通用信息
- `n_ff_exp = 2048`：每个专家的 FFN 宽度

### 5.5.3 MoE 的优势

```
传统 Dense FFN:
  所有参数每次都参与计算
  参数量 = 计算量

MoE FFN:
  256 个专家，每次只用 6 个
  总参数量 = 256 × 专家大小（很大）
  每次计算量 = 6 × 专家大小（很小）
  -> 用更多的参数，花更少的计算
```

这就是 DeepSeek V4 Flash 为什么"又强又快"的秘密：570 亿总参数，但每次推理只激活约 37 亿参数。

### 5.5.4 对应的权重

在 `ds4_layer_weights`（`ds4.c:4040`）中：

每个专家是一个标准 SwiGLU FFN（第 12 章详讲），有三个权重矩阵：

| 矩阵 | 作用 | 维度 | 类比 |
|------|------|------|------|
| **gate** | 门控投影：`silu(gate × x)` 决定哪些信息通过 | [2048, 4096] | 水龙头的阀门 |
| **up** | 内容投影：`up × x` 提供通过的信息内容 | [2048, 4096] | 水管里的水 |
| **down** | 降维投影：把中间结果映射回 4096 维 | [4096, 2048] | 汇总到出水口 |

SwiGLU 的计算：`output = down × (silu(gate × x) ⊙ up × x)`，即 gate 控制开关、up 提供内容、down 汇总输出。第 12 章会逐行讲解。

256 个路由专家 + 1 个共享专家的权重表：

| 权重 | 含义 | 形状 |
|------|------|------|
| `ffn_gate_inp` | 路由门控权重（给 256 个专家打分） | [256, 4096] |
| `ffn_gate_exps` | 256 个专家的 gate 矩阵打包 | [256, 2048, 4096] |
| `ffn_up_exps` | 256 个专家的 up 矩阵打包 | [256, 2048, 4096] |
| `ffn_down_exps` | 256 个专家的 down 矩阵打包 | [256, 4096, 2048] |
| `ffn_gate_shexp` | 共享专家的 gate 矩阵 | [2048, 4096] |
| `ffn_up_shexp` | 共享专家的 up 矩阵 | [2048, 4096] |
| `ffn_down_shexp` | 共享专家的 down 矩阵 | [4096, 2048] |

> **专家权重的存储**：256 个专家的权重打包存储在 `ffn_gate_exps`、`ffn_up_exps`、`ffn_down_exps` 三个三维张量里（`ds4.c:4929-4931` 验证维度）。推理时根据路由结果从中"抽取"6 个专家的权重来计算。这也是 SSD 流式加载的基础--可以只加载需要的 6 个专家，不用全部载入内存。

## 5.6 路由方式：Hash 路由与学习路由

DeepSeek V4 Flash 的 43 层中，路由方式分两段：

| 层范围 | 路由方式 | 判断依据 |
|--------|---------|---------|
| Layer 0-2（前 3 层） | **Hash 路由** | `n_hash_layer = 3`，这 3 层有 `ffn_gate_tid2eid` 张量 |
| Layer 3-42（后 40 层） | **学习路由** | `ffn_gate_tid2eid` 不存在，走门控打分 + top-k |

> **源码依据**：权重绑定时，只有 `il < DS4_N_HASH_LAYER` 的层才加载 `ffn_gate_tid2eid`（`ds4.c:5881`）。推理时 `layer_routed_moe_one` 检查 `layer->ffn_gate_tid2eid` 是否存在来决定路由方式（`ds4.c:10809`）。

### 两种路由的区别

```
学习路由 (Layer 3-42, 共 40 层):
  第 1 步 路由打分: matvec(ffn_gate_inp, x) -> 256 个分数
                    ← 对全部 256 个专家各打一个分（仍然只是打分，不跑专家 FFN）
                    ← 开销: 256 × 4096 ≈ 100 万次乘加
  第 2 步 激活:     softplus + sqrt 作用于每个分数
  第 3 步 选专家:   top-6 选择 + 权重归一化，得到 6 个专家编号 + 权重
  第 4 步 跑 FFN:   只对这 6 个专家执行 SwiGLU: gate @ x, up @ x, down @ mid
                    ← 开销: 6 × 3 × 2048 × 4096 ≈ 1.51 亿次乘加
                    ← 剩下 250 个专家一个乘加都不做
  ↑ 路由依赖输入内容 x，精度高
  ↑ 总开销 ≈ 1.51 亿 + 100 万（打分）≈ 1.51 亿次乘加 / token

Hash 路由 (Layer 0-2, 共 3 层):
  1. hash(token_id) -> 查表 ffn_gate_tid2eid -> 直接得到 6 个专家编号
  ↑ 不需要矩阵乘法，只需一次哈希 + 查表
  ↑ 路由不依赖输入内容，精度略低但极快
  ↑ 开销: 几乎为零
```

### 为什么前 3 层用 Hash 路由？

前几层 Token 刚经过 Embedding，特征尚未充分分化，学习路由学到的模式有限。用 hash 路由可以：
- 省掉 3 层的门控矩阵乘法（3 × 100 万 = 300 万次乘加）
- 路由结果虽然粗糙，但对前几层影响不大

后面的层特征已充分分化，需要精细路由，用学习路由。

### Hash 路由的权重仍用门控概率

即使选择用 hash，专家的**权重**仍通过门控概率计算（`ds4.c:10811`）：

```c
if (layer->ffn_gate_tid2eid) {
    layer_hash_selected_experts(selected, model, layer, token);     // hash 选专家
    layer_hash_router_weights_one(expert_weight, model, layer, x, selected); // 用门控概率算权重
} else {
    layer_topk_selected_experts(selected, expert_weight, model, layer, x);  // 学习路由选+算
}
```

这样 hash 路由的专家权重质量有保证--选择是 hash 的，但权重不是随机的。

> **GLM 5.2 的差异**：GLM 5.2 的 `n_hash_layer = 0`，全部 79 层都用学习路由，没有 hash 路由。

## 5.7 索引器：压缩历史

```
n_indexer_head = 64, n_indexer_head_dim = 128, n_indexer_top_k = 512
```

索引器（Indexer）是 DeepSeek V4 用于**压缩长上下文 KV 缓存**的机制。当上下文超过 SWA 窗口（128）时，旧的 KV 不是直接丢弃，而是被压缩成一个"索引"：

```
原始 KV 缓存:
  [token_0] [token_1] ... [token_500] [最近128个] [当前]
   └──────── 被压缩成索引 ────────┘

压缩后:
  [索引向量(512个)] [最近128个原始KV] [当前]
   ↑ 只有 512 个压缩槽位
```

这样，即使上下文有 10 万 token，实际的 KV 缓存也只有 `512 + 128` 个槽位，大幅节省内存。

## 5.8 完整架构一览

把所有部件组合起来，DeepSeek V4 Flash 的一层结构：

```
输入 (4096 维)
  │
  ├─ RMSNorm (attn_norm)
  │   │
  │   ├─ Q 压缩: attn_q_a (4096 → 1024)
  │   │   └─ Q 还原: attn_q_b (1024 → 32768)
  │   │       └─ RoPE 旋转 (n_rot=64)
  │   │
  │   ├─ KV 压缩: attn_kv_a_mqa (4096 → 压缩维度)
  │   │   └─ KV 还原: attn_k_b, attn_v_b
  │   │
  │   ├─ 注意力计算
  │   │   ├─ SWA 窗口内: 直接计算 (128 个)
  │   │   └─ 窗口外: 查索引器压缩缓存 (512 个)
  │   │
  │   └─ 输出投影: attn_output (低秩分解)
  │
  ├─ 残差连接
  │
  ├─ RMSNorm (ffn_norm)
  │   │
  │   ├─ 路由门控: ffn_gate_inp → 选 6 个专家
  │   │
  │   ├─ 共享专家: ffn_gate_shexp → ffn_up_shexp → SwiGLU → ffn_down_shexp
  │   │
  │   ├─ 路由专家 ×6: ffn_gate_exps → ffn_up_exps → SwiGLU → ffn_down_exps
  │   │
  │   └─ 加权求和: 6 个路由专家 + 1 个共享专家
  │
  ├─ 残差连接
  │
  ▼
输出 (4096 维) → 下一层
```

## 5.9 参数量估算

让我们对照 `ds4.c:535` 的 `DS4_SHAPE_FLASH`，逐项算出 DeepSeek V4 Flash 的总参数量。下表先列出后面要用到的常量：

```
常量（来源 DS4_SHAPE_FLASH，ds4.c:535）：
  n_embd          = 4096   // 嵌入维度 d_model
  n_head          = 64     // 注意力头数
  n_head_dim      = 512    // 每个头的维度
  n_lora_q        = 1024   // Q 的低秩压缩维度
  n_lora_o        = 1024   // O (output) 的低秩压缩维度
  n_out_group     = 8      // Output 投影的分组数
  n_ff_exp        = 2048   // 每个专家的中间维度
  n_expert        = 256    // 路由专家数
  n_expert_used   = 6      // 每 token 激活的专家数
  n_expert_shared = 1      // 共享专家数
  n_layer         = 43     // 层数
  n_vocab         = 129280 // 词表大小
```

### 5.9.1 Embedding 与 Output head

```
token_embd: [n_vocab, n_embd]    = 129280 × 4096  = 529,530,880  ≈ 5.30 亿
output:     [n_vocab, n_embd]    = 129280 × 4096  = 529,530,880  ≈ 5.30 亿
小计:                                            1,059,061,760  ≈ 10.60 亿
```

### 5.9.2 每层 Attention

逐张量查 `ds4.c:5006-5083` 的 `tensor_expect_*` 布局声明，可得到每个注意力张量的真实形状。MLA 把 Q、KV、Output 都做了低秩分解，所以一共要算 5 个矩阵：

| 张量 | 形状 | 参数量 | 来源 |
|------|------|--------|------|
| `attn_q_a` | `[n_embd, n_lora_q]` | 4096 × 1024 = 4.19M | `ds4.c:5007` |
| `attn_q_b` | `[n_lora_q, n_head × n_head_dim]` | 1024 × (64×512) = 33.55M | `ds4.c:5009` |
| `attn_kv` | `[n_embd, n_head_dim]` | 4096 × 512 = 2.10M | `ds4.c:5010` |
| `attn_output_a` | `[n_head_dim × (n_head / n_out_group), n_out_group × n_lora_o]` | 4096 × 8192 = 33.55M | `ds4.c:5013` |
| `attn_output_b` | `[n_out_group × n_lora_o, n_embd]` | 8192 × 4096 = 33.55M | `ds4.c:5014` |
| **合计** | | **≈ 107M ≈ 1.07 亿** | |

几个常被误算的地方：

- **KV 不是 30M，而是 2.10M**。`attn_kv` 是 MQA 风格的共享 KV 投影（`kv_a_mqa`），从 `n_embd=4096` 压缩到 `n_head_dim=512`，所以只有 4096 × 512 = 2.10M。MLA 的核心收益正是在这里——传统注意力的 KV 是 `[n_embd, 2 × n_head × n_head_dim] = [4096, 65536] ≈ 268M`，MLA 把 KV 矩阵砍到 1/128。
- **Output 也不是 ~20M，而是 67M**。Output 也做了低秩分解：`attn_output_a` 是 `[4096, 8192] = 33.55M`，`attn_output_b` 是 `[8192, 4096] = 33.55M`，加起来 67.10M。其中分组维度 `n_out_group=8` 把 64 个头分成 8 组共享一个低秩瓶颈。
- 这里的 1.07 亿是**参数**个数，不是字节数。每个参数存为 `Q8_0`（8 bit），所以 attention 权重实际占 `107M × 1 byte = 107 MB / 层`。

### 5.9.3 每层 MoE

专家矩阵同样能在 `ds4.c:5066-5071` 查到。每个专家是一个 SwiGLU FFN，包含三个矩阵：

```
每个专家的 FFN（SwiGLU）:
  gate: [n_ff_exp, n_embd]  = 2048 × 4096  = 8,388,608  ≈ 8.39M
  up:   [n_ff_exp, n_embd]  = 2048 × 4096  = 8,388,608  ≈ 8.39M
  down: [n_embd, n_ff_exp]  = 4096 × 2048  = 8,388,608  ≈ 8.39M
  合计 / 专家                            ≈ 25.17M
```

计算过程就是线性代数里的矩阵乘法：

- `gate @ x`：输入 x 维度是 `n_embd=4096`，门控矩阵形状 `[2048, 4096]`，输出 2048 维向量。
- `up @ x`：同形状，输出 2048 维向量。
- `down @ (silu(gate(x)) ⊙ up(x))`：中间 2048 维向量乘以矩阵 `[4096, 2048]`，回到 `n_embd=4096`。

所以矩阵形状的"行 × 列"对应"输出维度 × 输入维度"，**2048 来自 `n_ff_exp`（专家中间维度），4096 来自 `n_embd`（模型维度）**。

然后把专家数量乘进去：

```
256 个路由专家 × (2048×4096 + 2048×4096 + 4096×2048)
   = 256 × (8.39M + 8.39M + 8.39M)
   = 256 × 25.17M
   = 6,442,450,944
   ≈ 64.4 亿  ← 这是参数个数，不是字节
```

> 公式末尾**没有 × 2**。`× 2` 是 FP16/BF16 存储时的字节换算系数，但 `IQ2_XSS` 这种 2-bit 量化下平均每参数只占 0.25 字节（再加分块 scale），所以 64.4 亿是纯参数计数。实际存盘大小要看 §5.9.6 的存储换算。

共享专家只多了 1 个，所以：

```
共享专家 (1 个 × 25.17M) = 25.17M ≈ 0.25 亿
路由门控 ffn_gate_inp: [n_embd, n_expert] = 4096 × 256 = 1.05M
```

### 5.9.4 每层小结

```
Attention         ≈ 1.07 亿
256 路由专家       ≈ 64.40 亿
1 个共享专家       ≈ 0.25 亿
路由门控           ≈ 0.01 亿
─────────────────────────────────
每层合计           ≈ 65.73 亿
```

### 5.9.5 总参数

```
43 层 × 65.73 亿        ≈ 2,826 亿
Embedding + Output head  ≈ 10.6 亿
─────────────────────────────────
模型总参数               ≈ 2,837 亿  ≈ 28.4 × 10^9  ≈ 28B
```

DS4 配置里 `DS4_SHAPE_FLASH` 描述的就是这个规模，加上 MTP block（`ds4.c:6497`）和 indexer 稀疏注意力等小开销，实际工程文件中的 293B 是个近似标称值；理论逐项相加约 28B，差值主要在量化元数据、稀疏 attention 索引、MTP 共享权重这些"额外但非主体"的部分。

### 5.9.6 存盘大小

```
28B 参数 × IQ2_XSS (≈ 2.6 bit 含 scale) ≈ 73 GB
Attention/Embedding × Q8_0 (8 bit)        ≈ 13 GB
─────────────────────────────────────────────
合计                                     ≈ 86 GB  -- 实际文件大小吻合
```

## 本章小结

- DeepSeek V4 Flash = 43 层 Transformer，嵌入维度 4096
- 注意力用 MLA + GQA(64:1) + SWA(128) + HC(4组) 四重优化
- MoE 每层 256 选 6 + 1 共享，总参数大但激活参数小
- 前 3 层用 hash 路由，后面用学习路由
- 索引器把超长上下文的 KV 压缩成 512 个槽位
- 架构参数全部定义在 `ds4.c:535` 的 `DS4_SHAPE_FLASH`
