# 第 18 章 量化技术：用更少比特存权重

## 本章导读

86GB 的模型如果用 F32 存需要 228GB--大多数机器装不下。量化技术把权重从 32 位压缩到 2-8 位，让大模型能在消费级硬件上运行。这章我们拆解 ds4 中的量化格式和反量化计算。

读完本章你会理解：
- 量化的基本原理：缩放因子 + 整数量
- Q8_0、Q2_K、IQ2_XXS 的块结构
- 反量化点积的计算过程
- 为什么混合量化比单一量化更好
- FP8 KV 量化的原理

**前置知识**：第 4-5 章

## 18.1 量化的基本原理

量化的核心思想：**浮点数太占空间，用整数代替**。

```
原始 F32 权重: 0.123, -0.456, 0.789, ...  (每个 4 字节)
量化后 Q8:     12, -46, 79, ...            (每个 1 字节)
               ↑ 精度降低但体积减小 4 倍

反量化: value = scale × quantized_int
  scale = 0.01 (缩放因子)
  0.123 ≈ 0.01 × 12 = 0.12
```

### 为什么不能直接截断？

直接把 F32 转成 int8 会丢失大量信息（F32 的范围是 ±3.4×10^38，int8 只有 -128~127）。所以需要**缩放因子**：

```
一组 32 个权重: [0.1, -0.3, 0.5, 0.2, ...]
最大绝对值: 0.5
缩放因子: scale = 0.5 / 127 ≈ 0.004

量化: q[i] = round(w[i] / scale)
  0.1 / 0.004 = 25
  -0.3 / 0.004 = -75
  0.5 / 0.004 = 127

反量化: w[i] ≈ scale × q[i]
  0.004 × 25 = 0.1  ✓
  0.004 × -75 = -0.3  ✓
  0.004 × 127 = 0.508  ≈0.5 ✓
```

> **关键设计**：不是整个张量用一个缩放因子，而是**分组（block）存储**--每 32 或 256 个元素一组，各有独立的缩放因子。这样不同区域的权重可以用不同的精度，整体误差更小。

## 18.2 Q8_0：8 位量化

Q8_0 是最简单的量化格式，也是理解其他格式的基础。

### 块结构

```
Q8_0 块 (34 字节, 32 个元素):
  ┌──────────────────┬──────────────────────────────────┐
  │ scale (F16, 2B)  │ q[0] q[1] ... q[31] (int8, 32B)  │
  └──────────────────┴──────────────────────────────────┘
  
  scale: 这 32 个元素的缩放因子 (半精度浮点)
  q[i]:  量化后的整数值 (-128 ~ 127)
  
  实际值 = scale × q[i]
  每元素: 34/32 = 8.5 bit (接近 1 字节)
```

定义在 `ds4.c:800` 的静态断言确认大小：
```c
// gguf_types[8] = {"q8_0", 32, 34}  // 32 元素, 34 字节
```

### 源码：Q8_0 点积

`dot_q8_0_row_f32_ref()`（`ds4.c:7546`）是 Q8_0 权重和 F32 输入的点积：

```c
static inline float dot_q8_0_row_f32_ref(
        const uint8_t *row,    // Q8_0 量化权重
        const float *x,        // F32 输入
        uint64_t in_dim,       // 维度
        uint64_t blocks) {     // 块数
    float acc = 0.0f;
    for (uint64_t b = 0; b < blocks; b++) {
        // 读缩放因子 (2 字节 F16)
        uint16_t scale_bits;
        memcpy(&scale_bits, row + b * 34, sizeof(scale_bits));
        const float d = f16_to_f32(scale_bits);

        // 读 32 个量化值 (32 字节 int8)
        const int8_t *qs = (const int8_t *)(row + b * 34 + 2);

        // 反量化 + 点积累加
        const uint64_t i0 = b * 32;
        for (uint64_t i = 0; i < 32; i++) {
            acc += d * (float)qs[i] * x[i0 + i];
            //   ↑ scale × 量化值 × 输入值
        }
    }
    return acc;
}
```

### 计算过程

```
点积 = Σ (scale_b × q_b[i] × x_b[i])

每个块:
  scale = f16_to_f32(读取的 2 字节)
  for i in [0..31]:
    acc += scale × q[i] × x[i]
    
优化: scale 可以提到块外面
  acc += scale × Σ(q[i] × x[i])
  -> 只做一次乘法 scale × (int8 × float 的和)
```

> **为什么 Q8_0 快？** int8 运算比 float 快 4 倍（SIMD 可以一次处理 16 个 int8 vs 4 个 float）。而且 int8 数据量小，内存带宽压力低。

## 18.3 Q2_K：2 位 K-quant

Q2_K 是更激进的压缩，每元素只占约 2.6 bit。

### 块结构

```
Q2_K 块 (84 字节, 256 个元素):
  ┌──────────┬────────────────────┬──────────────────────────────────┐
  │ d (F16)  │ scales (16 × FP4)  │ qs (64 × uint8 = 256 × 2bit)    │
  │ 2 字节   │ 16 字节             │ 64 字节                           │
  └──────────┴────────────────────┴──────────────────────────────────┘

  d: 全局缩放因子
  scales: 16 个子组缩放 (4 bit 浮点)
  qs: 256 个 2-bit 量化值 (打包在 64 字节中)

  实际值 = d × scales[j] × q2_value
  每元素: 84/256 ≈ 2.6 bit
```

### 分层缩放

Q2_K 用了**两级缩放**：

```
全局: d (1 个 F16)
子组: scales[16] (16 个 4-bit 值, 每 16 个元素共享一个)

value = d × scales[j] × q2[i]
         ↑全局  ↑子组级   ↑2-bit 量化
```

两级缩放让不同区域的精度可以自适应：数值大的区域用大缩放因子，数值小的区域用小缩放因子。

### 点积实现

`ds4_vec_dot_q2_K_q8_K()`（`ds4.c:3346`）做 Q2_K 权重和 Q8_K 输入的点积。逻辑比 Q8_0 复杂得多，需要解码 2-bit 打包值和 4-bit 缩放因子，但原理相同：反量化 + 累加。

## 18.4 IQ2_XXS：2 位重要性矩阵量化

IQ2_XXS 是 ds4 中最激进的量化，每元素仅 2.06 bit。它用于路由专家权重（模型中最大的部分）。

### 与 Q2_K 的区别

```
Q2_K:   均匀量化 + 两级缩放
IQ2_XXS: 非均匀量化 + 查找表 + 重要性矩阵

  - 使用 "importance matrix" (imatrix): 训练时统计的权重重要性
  - 重要的权重用更多比特，不重要的用更少
  - 2-bit 值通过查找表 (lookup table) 映射到实际值
  - 压缩比极高，但解压计算更复杂
```

### 块结构

```
IQ2_XXS 块 (66 字节, 256 个元素):
  每元素: 66/256 ≈ 2.06 bit

  包含:
  - 2-bit 量化值 (打包存储)
  - 缩放因子
  - 查找表索引
```

`ds4_vec_dot_iq2_xxs_q8_K()` 做 IQ2_XXS 和 Q8_K 的点积，需要查表解码。虽然解压更复杂，但由于路由专家只在 256 选 6 时使用，总计算量可控。

## 18.5 混合量化策略

DeepSeek V4 Flash 不是用单一量化格式，而是**混合量化**：

```
文件名: IQ2XXS-w2Q2K-AProjQ8-SExpQ8-OutQ8

  路由专家权重:  IQ2_XXS (2 bit)    ← 最大体积, 最激进压缩
  下投影权重:    Q2_K (2.6 bit)     ← 体积大, 高压缩
  注意力投影:    Q8_0 (8.5 bit)     ← 精度敏感, 高精度
  共享专家:      Q8_0 (8.5 bit)     ← 每次都算, 需要精度
  输出头:        Q8_0 (8.5 bit)     ← 直接影响输出, 高精度
```

### 为什么这样设计？

```
路由专家 (256 个, 每次只用 6 个):
  - 总体积最大 (256 × 3 个大矩阵)
  - 但每次只激活 6 个, 单次计算量小
  - 量化误差被 6 个专家平均, 影响分散
  -> 可以用最激进的 IQ2_XXS

注意力投影 (Q/KV/Output):
  - 每次都参与计算
  - 直接影响注意力质量
  - 量化误差会层层累积
  -> 需要 Q8_0 高精度

共享专家:
  - 每次都参与, 误差不可分散
  -> 需要 Q8_0
```

> **核心原则**：对精度敏感且频繁使用的权重用高精度，对精度不敏感或使用稀疏的权重用低精度。这样在体积和质量之间取得最佳平衡。

## 18.6 FP8 KV 量化

除了权重量化，ds4 还对 **KV 缓存**做 FP8 量化（第 15 章提到过）：

```c
// ds4.c:13519
dsv4_fp8_kv_quantize_row_inplace_cpu(scratch->kv, DS4_N_HEAD_DIM, DS4_N_ROT);
```

### FP8 vs F16

```
F16: 1 符号 + 5 指数 + 10 尾数 = 16 bit
FP8: 1 符号 + 4 指数 + 3 尾数 = 8 bit

KV 缓存:
  F16: 128 × 512 × 2 = 128 KB / 每层
  FP8: 128 × 512 × 1 = 64 KB / 每层  ← 减半！
  43 层: 2.75 MB (FP8) vs 5.5 MB (F16)
```

FP8 的精度比 F16 低，但对于 KV 缓存（注意力的中间结果）来说够用。减半的内存让长上下文的缓存压力大幅降低。

## 18.7 量化对性能和质量的影响

### 性能

```
计算速度 (相对 F32):
  Q8_0:  ~3-4x 更快 (int8 运算 + 减少内存读取)
  Q2_K:  ~2-3x 更快 (虽然解压复杂, 但内存读取减少更多)
  IQ2_XXS: ~2x 更快 (解压开销大, 但内存读取极少)

内存占用 (相对 F32):
  Q8_0:    1/4
  Q2_K:    1/12
  IQ2_XXS: 1/15
```

### 质量

```
量化误差 (perplexity 增加):
  Q8_0:     ~0.1%  (几乎无损)
  Q4_K:     ~1%    (轻微损失)
  Q2_K:     ~3-5%  (可接受)
  IQ2_XXS:  ~5-8%  (有损失, 但 imatrix 补偿)
```

> **DSpark 的角色**：DSpark 是一种推测解码增强技术，部分原因是为了弥补激进量化（IQ2_XXS）带来的质量损失。通过更聪明的推测解码，在保持速度的同时提升输出质量。

## 本章小结

- 量化 = 用整数代替浮点数 + 缩放因子，大幅减少存储和计算
- Q8_0：每 32 元素一组，1 个 F16 缩放 + 32 个 int8，8.5 bit/元素
- Q2_K：每 256 元素一组，两级缩放（全局 + 子组），2.6 bit/元素
- IQ2_XXS：重要性矩阵 + 查找表，2.06 bit/元素，最激进
- 混合量化：路由专家 IQ2_XXS，注意力/共享专家 Q8_0
- FP8 KV 量化把缓存减半
- 量化的精度损失通过 imatrix 和混合策略弥补
